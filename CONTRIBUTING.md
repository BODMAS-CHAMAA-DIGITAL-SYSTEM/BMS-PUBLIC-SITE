# Contributing

1. Confirm the issue and intended change with the project maintainer.
2. Create a focused branch from the agreed base branch.
3. Keep changes within this repository's stated responsibility.
4. Do not commit credentials, private member data, payment data or production dumps.
5. Add or update tests and documentation for behaviour changes.
6. Run the relevant checks locally before opening a pull request.
7. Describe the change, validation performed, deployment impact and any migration requirements.

Changes affecting shared API contracts, authentication, financial calculations,
database schemas or payment processing must be reviewed for cross-repository impact.
